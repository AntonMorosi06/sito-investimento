# MicroBot Labs — NODE_01_LED_STATE Expected Output Specification v0.3

Status: expected-output specification  
Created: 2026-05-16  
Applies to: simulated pre-hardware validation and future real ESP32 validation  
Hardware validation status: not hardware-validated by this document

## 1. Purpose

This document defines the expected command/response and state behavior for `NODE_01_LED_STATE`.

It supports both:

- the pre-hardware mock responder;
- the future real ESP32 LED node test.

## 2. Expected identity

Expected node identity:

- node id: `NODE_01_LED_STATE`
- role: `LED_STATE_NODE`
- target: `PC_CONTROLLER`
- validation mode when simulated: `PRE_HARDWARE_SIMULATED`

## 3. Expected response structure

Each response should contain:

- `version`
- `validation_mode` when simulated;
- `type`;
- `source`;
- `target`;
- `seq`;
- `uptime_ms`;
- `command`;
- `status`;
- `state`;
- `payload`.

## 4. Expected commands

| Command | Expected result |
|---|---|
| `PING` | `OK` response containing `PONG` |
| `STATUS` | `OK` response identifying `NODE_01_LED_STATE` |
| `ACTIVE` | transition to `ACTIVE`, virtual LED `ON` |
| `IDLE` | transition to `IDLE`, virtual LED `OFF` |
| `WARNING` | transition to `WARNING`, virtual LED `BLINK_SLOW` |
| `ERROR` | transition to `ERROR`, virtual LED `BLINK_FAST` |
| `SET_LED ACTIVE` | transition to `ACTIVE`, virtual LED `ON` |
| `SET_STATE ACTIVE` | transition to `ACTIVE`, virtual LED `ON` |
| `STOP` | transition to `SAFE_MODE`, virtual LED `BLINK_SAFETY` |
| `RESET` | transition to `READY`, virtual LED `OFF` |
| unknown command | structured error response |

## 5. Expected safety behavior

Safety behavior must remain simple and explicit.

Expected rules:

- `STOP` always moves NODE_01 to `SAFE_MODE`.
- `RESET` always moves NODE_01 back to `READY`.
- `ERROR` must not be confused with real hardware failure in simulation.
- Unknown commands must be rejected.
- Simulated LED state must not be described as real GPIO output.

## 6. Future real hardware comparison

The future real test should compare:

- simulated response structure;
- real serial response structure;
- simulated state transition;
- real observed LED state;
- report generated by test script;
- optional photo/video evidence.

Only real hardware evidence can upgrade NODE_01 from pre-hardware simulated to hardware-validated.
