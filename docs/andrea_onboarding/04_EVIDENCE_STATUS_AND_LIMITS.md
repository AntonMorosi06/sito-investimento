# 04 — Evidence, Status and Limits

Status: evidence explanation  
Audience: Andrea

## Current status

The repository is currently:

```text
v0.3 pre-hardware and hardware-integration preparation
```

Hardware validation status:

```text
not yet hardware-validated
```

## Evidence that exists

The repository contains:

- documentation;
- current evidence map;
- repository map;
- firmware targets;
- simulated NODE_00 output;
- simulated NODE_01 output;
- dashboard parser validation;
- setup and purchase guides;
- generated reports and logs.

## Evidence that does not exist yet

The repository does not yet contain:

- real ESP32 upload evidence;
- real NODE_00 serial hardware report;
- real NODE_01 LED hardware report;
- real LED photo/video evidence;
- real Web Serial hardware dashboard test;
- real sensor evidence;
- real magnetic docking evidence;
- real wireless swarm evidence.

## Allowed claim

Andrea can say:

```text
MicroBot Labs has a structured pre-hardware validation baseline and a hardware-ready path toward first ESP32 tests.
```

## Not allowed claim

Andrea should not say:

```text
MicroBot Labs has a completed physical swarm.
```

Andrea should not say:

```text
MicroBot Labs has validated real hardware.
```

Until real ESP32 logs and visible LED evidence are committed, hardware is still pending.

## Why this distinction matters

This distinction is what makes the project credible.

A weaker project would pretend that simulations are hardware.

A stronger project separates:

```text
planned
prepared
mocked
validated offline
pre-hardware simulated
hardware-ready
hardware-validated
```
