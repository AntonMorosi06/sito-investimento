# MicroBot Labs — Dashboard Mock Output Test Plan v0.3

Status: dashboard/mock-output test plan  
Created: 2026-05-16  
Hardware validation status: not hardware-validated  
Test source: pre-hardware simulated NODE_00_MASTER output

## 1. Purpose

This test plan defines how the dashboard should be tested against the simulated NODE_00_MASTER output before real ESP32 hardware is available.

The goal is to validate the parser and dashboard interpretation path, not hardware.

## 2. Test input

The input is the simulated JSONL output generated by:

    python3 tools/offline/mock_node00_master_responder.py

Expected output location:

    demos/demo_v0_3/pre_hardware_mock_node00_master/logs/

The JSONL file contains rows where each row wraps a simulated packet and includes the label:

    PRE_HARDWARE_SIMULATED

## 3. Test scope

This test should check:

- JSON line availability;
- packet parseability;
- packet type recognition;
- Master identity recognition;
- PING/PONG command response;
- STATUS response;
- node table response;
- scan placeholder response;
- STOP to SAFE_MODE transition;
- RESET to READY transition;
- preservation of simulated validation mode.

## 4. Test cases

| Test ID | Input | Expected result |
|---|---|---|
| DASH-MOCK-001 | Boot simulated event | Parser accepts event packet |
| DASH-MOCK-002 | Heartbeat simulated packet | Parser accepts heartbeat packet |
| DASH-MOCK-003 | PING response | Dashboard can identify PONG |
| DASH-MOCK-004 | STATUS response | Dashboard can identify NODE_00_MASTER |
| DASH-MOCK-005 | GET_NODE_TABLE response | Dashboard can identify expected node IDs |
| DASH-MOCK-006 | SCAN_NODES response | Dashboard can identify placeholder scan result |
| DASH-MOCK-007 | STOP response | Dashboard can identify SAFE_MODE |
| DASH-MOCK-008 | RESET response | Dashboard can identify READY |
| DASH-MOCK-009 | PRE_HARDWARE_SIMULATED label | Dashboard or report preserves simulated source |
| DASH-MOCK-010 | Unknown or malformed future line | Parser returns structured error without crashing |

## 5. Acceptance criteria

The dashboard/mock-output integration can be considered prepared when:

- simulated JSONL exists;
- dashboard parser requirements are documented;
- packet mapping rules are documented;
- the dashboard state mapping does not imply hardware validation;
- future parser tests can be added without changing the overall evidence model.

## 6. Non-goals

This test does not validate:

- USB Serial;
- Web Serial;
- ESP32 firmware upload;
- physical board response;
- GPIO output;
- LED output;
- sensors;
- batteries;
- wireless communication;
- magnetic docking.

## 7. Next step

The next useful file after this test plan is a small offline parser validation script that reads the generated simulated JSONL and checks whether the dashboard-facing packet fields are present.
